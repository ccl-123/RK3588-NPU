## 系统简介

### 什么是人脸识别考勤系统？

这是一款基于 RK3588 平台的高性能人脸识别考勤系统，采用深度学习技术实现实时人脸检测、识别和考勤记录。

### 主要特点

- ✅ **实时识别**: 60+ FPS 高帧率，毫秒级响应
- ✅ **高准确率**: 良好光照条件下识别准确率 >95%
- ✅ **自动考勤**: 识别成功后自动记录签到/签退
- ✅ **数据持久化**: SQLite 数据库存储，数据安全可靠
- ✅ **友好界面**: Qt 图形界面，操作简单直观

## 快速开始

### 1. 启动系统

```bash
cd /home/firefly/open_project/edge2-npu/C++/face_recognition_cap/install/face_recognition_cap
./run_gui.sh
```

### 2. 打开摄像头

- 点击菜单栏 **文件 → 打开摄像头**
- 或点击工具栏的 **▶ 开始** 按钮
- 等待摄像头初始化（约 2-3 秒）

### 3. 注册第一个用户

1. 点击菜单栏 **用户 → 注册人脸**
2. 填写用户信息：
   - **姓名**（必填）
   - 工号（可选）
   - 部门（可选）
3. 调整姿势，确保人脸清晰可见
4. 点击 **采集** 按钮，采集 3-5 张人脸照片
5. 点击 **注册** 按钮完成注册

### 4. 开始考勤

- 用户站在摄像头前
- 系统自动识别并显示姓名和相似度
- 自动记录签到/签退时间
- 30 分钟内不会重复记录

### 人脸注册详解

#### 注册步骤

1. **填写用户信息**
   - 姓名：必填，用于识别显示
   - 工号：可选，便于管理
   - 部门：可选，从下拉列表选择

2. **采集人脸照片**
   - 保持正面面对摄像头
   - 确保光线充足
   - 避免遮挡（口罩、墨镜等）
   - 采集 3-5 张不同角度的照片

3. **质量检测**
   - 系统自动检测人脸质量
   - 光线太暗/太亮会提示调整
   - 人脸太小会提示靠近摄像头

4. **完成注册**
   - 点击注册按钮
   - 系统保存用户信息和人脸特征
   - 自动重新加载特征库

#### 注意事项

- ⚠️ 每次采集确保只有一张人脸
- ⚠️ 采集时保持自然表情
- ⚠️ 建议在实际使用环境中采集
- ⚠️ 至少采集 3 张照片才能注册

### 系统设置详解

#### 摄像头设置

- **摄像头类型**: USB 或 MIPI
- **设备编号**: 摄像头设备号（如 21）
- **分辨率**: 宽度 x 高度（默认 1280x720）
- **异步读取**: 启用可提高 USB 摄像头性能

#### 识别参数

- **人脸检测置信度**: 0.1-1.0（默认 0.7）
  - 越高越严格，减少误检
  - 越低越宽松，增加检出率

- **NMS 阈值**: 0.1-1.0（默认 0.6）
  - 用于去除重叠的人脸框

- **人脸识别阈值**: 0.1-1.0（默认 0.5）
  - 越高越严格，减少误识别
  - 越低越宽松，增加识别率

#### 性能设置

- **性能报告间隔**: 每 N 帧输出一次性能日志

## 常见问题

### Q1: 识别不准确怎么办？

**A**: 尝试以下方法：
1. 增加采集照片数量（5 张）
2. 在不同光照条件下采集
3. 调整识别阈值（降低到 0.4-0.45）
4. 确保摄像头清晰度足够

### Q2: 识别速度慢怎么办？

**A**: 
1. 检查 CPU/NPU 占用率
2. 降低摄像头分辨率（如 640x480）
3. 启用 USB 异步读取
4. 关闭其他占用资源的程序

### Q3: 无法打开摄像头？

**A**:
1. 检查摄像头是否连接
2. 确认设备编号正确（`ls /dev/video*`）
3. 检查权限（`sudo chmod 666 /dev/video*`）
4. 尝试重启程序

### Q4: 考勤记录丢失？

**A**:
1. 检查数据库文件是否存在
2. 查看日志文件（`logs/` 目录）
3. 使用 db_tool 查询数据库
4. 定期备份数据库文件

### Q5: 如何删除错误的考勤记录？

**A**:
使用 db_tool 命令行工具：
```bash
./db_tool data/database/face_recognition.db delete_attendance <record_id>
```

## 故障排除

### 程序崩溃

1. 查看日志文件：`logs/face_recognition.log`
2. 检查数据库完整性
3. 重新编译程序
4. 联系技术支持

### 性能下降

1. 重启程序
2. 清理数据库（删除旧记录）
3. 检查系统资源占用
4. 更新 RKNN 驱动

### 界面卡顿

1. 降低刷新率
2. 关闭不必要的停靠窗口
3. 减少用户数量
4. 优化数据库索引
