# 开发者文档

本文档为参与本项目开发的工程师提供核心指南。

## 🛠 开发环境要求

- **硬件**: Firefly RK3588 系列开发板 (如 EC-A3588Q)。
- **操作系统**: Ubuntu 22.04 LTS (ARM64)。
- **工具链**: 
  - 编译器: GCC/G++ 11.4+ (必须支持 **C++17**)。
  - 构建工具: CMake 3.14+。
- **核心依赖**:
  - **Qt 5.15+**: 用于 GUI 界面。
  - **OpenCV 4.x**: 图像处理。
  - **SQLite3**: 数据库。
  - **RKNN Runtime**: 2.x 系列版本。
  - **spdlog**: 高性能日志。

## 🚀 开发流程

### 1. 编译构建
项目支持一键编译，会自动识别 aarch64 环境。
```bash
bash build.sh
```

### 2. 数据库管理
使用内置工具 `db_tool` 进行人员初始化：
```bash
# 初始化数据库架构
./db_tool init data/database/face_recognition.db
# 添加测试用户
./db_tool add_user data/database/face_recognition.db "张三" "研发部"
```

## 🏗 核心类图逻辑

1.  **FaceRecognitionApp**: 持有所有流水线线程 (`std::unique_ptr`)。
2.  **PreprocessingThread**: 通过 `CameraUtil` 异步获取帧，利用 `std::shared_ptr` 实现数据在后续线程的零拷贝流转。
3.  **RecognitionThread**: 在检测到人脸后，触发 `RecognitionCallback` 同步业务状态。

### 智能分析系统集成 (AI Agent)

系统集成了基于 LLM 的智能分析对话系统，架构如下：

- **AiAnalysisService**: 核心服务类，管理与云端大模型的会话生命周期。
  - **通信协议**: 采用 **SSE (Server-Sent Events)** 流式传输协议，实现打字机效果的实时响应。
  - **上下文管理**: 自动组装当前时间、多维度考勤统计（今日/7日/30日）及详细打卡流水作为 Prompt 上下文。
  - **容错机制**: 内置指数退避重试策略 (Exponential Backoff)，应对网络波动或并发限制。
  - **隐私安全**: 仅发送必要的脱敏考勤数据，不上传人脸图片或生物特征。

## ⚠️ 内存安全与同步

- **cv::Mat**: 严禁在线程间传递时手动管理内存，必须利用其内置的引用计数机制。
- **Atomic Flags**: 线程的启停状态使用 `std::atomic<bool>`。
- **Zero-Copy**: `CameraUtil` 返回的 `cv::Mat` 直接指向 `mmap` 的映射区域或其解码缓存，处理耗时长的模块如需保留数据，必须显式 `.clone()`。

## 🛡 最佳实践

- **业务逻辑卸载**: 数据库写操作、音频播放等耗时操作必须在 `on_recognition_result` 回调中通过信号槽 (`Qt::QueuedConnection`) 异步执行，严禁阻塞 `RecognitionThread`。
- **日志规范**: 使用 `spdlog`。
  - 调试算法流：`spdlog::trace`
  - 业务状态：`spdlog::info`
  - 硬件异常：`spdlog::error`
