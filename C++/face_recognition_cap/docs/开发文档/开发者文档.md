# 开发者文档

> 版本: v2.4
> 更新日期: 2026-04-01

## 开发环境

- 硬件：RK3588 系列开发板，如 EC-A3588Q、Rock 5B、Orange Pi 5
- 操作系统：Ubuntu 22.04
- 编译器：GCC / G++ 11.4+
- 构建工具：CMake 3.14+
- 关键依赖：
  - Qt 5.15+
  - OpenCV 4.x
  - SQLite3
  - RKNN Runtime
  - RKLLM Runtime
  - spdlog / fmt

## 工程结构

```text

├── include/
│   ├── agent/          # ReAct Agent、工具执行、对话记忆

│   ├── core/           # YOLO / FaceNet 核心算法封装

├── src/
├── gui/
├── data/
├── docs/
├── build.sh
└── cross_build.sh
```

## 构建方式

### 板端直接构建

```bash
cd C++/face_recognition_cap
./build.sh
```

### 交叉编译

```bash
cd C++/face_recognition_cap
./cross_build.sh --build
```

说明：

- `./build.sh` 更适合板端本地开发
- `./cross_build.sh --build` 更适合 PC -> RK3588 的交叉构建

## LLM 接入方式

当前项目支持 3 种大模型路径：

### 1. 本地 RKLLM

```bash
export LOCAL_LLM_MODEL_PATH=/path/to/your_model.rkllm
```

### 2. 腾讯云 LKE

```bash
export TENCENT_APP_KEY=your_app_key
export TENCENT_SECRET_ID=your_secret_id
export TENCENT_SECRET_KEY=your_secret_key
```

### 3. OpenAI 兼容远端接口

```bash
export LLAMA_CPP_SERVER_URL=http://127.0.0.1:8080
export LLAMA_CPP_SERVER_MODEL=gpt-4o-mini
export LLAMA_CPP_SERVER_API_KEY=sk-your-key
```

说明：

- 当 `LLAMA_CPP_SERVER_URL` 非空时，远端模式自动切换到 OpenAI 兼容接口
- 代码会自动拼接 `/v1/chat/completions`
- 变量名保留 `LLAMA_CPP_*` 历史前缀，但后端不要求必须是 llama.cpp

详见：

- [OpenAI兼容接口接入说明.md](./OpenAI兼容接口接入说明.md)

## Agent 工具系统

当前默认注册工具包括：

- `query_attendance`
- `lookup_user_attendance`
- `lookup_department_attendance`
- `lookup_attendance_ranking`
- `lookup_missing_attendance`
- `query_user`
- `system_info`
- `help`
- `calculator`

这些工具统一由：

- `ToolRegistry`
- `ToolExecutor`
- `ReactAgent`
- `AgentService`

串起来工作。

## 新增工具时不要漏改

新增 Agent 工具时，不要只写 `.cc` 和 `.h`，至少还要同步改：

1. `AgentService::registerBuiltinTools()`
2. `CMakeLists.txt`
3. `system_tool.cc` 中的 `HelpTool`
4. `PromptTemplates`
5. 相关开发文档 / 用户文档 / README

否则会出现代码里已经有工具，但模型提示词和帮助里不知道它存在的漂移问题。

## 数据库与业务层

核心业务类：

- `AttendanceService`
- `UserService`

常见 DAO：

- `AttendanceRecordDAO`
- `UserDAO`
- `FaceFeatureDAO`

新增的部门、排行、缺卡工具都依赖：

- `users`
- `attendance_records`

因此如果以后要继续增强 Agent，优先考虑复用现有 `Service` 层，不要直接在工具里写原始 SQL。

## 调试建议

- 算法与推理链路：看 `spdlog::debug`
- 远端请求问题：优先看 `AiAnalysisService`
- 本地模型问题：优先看 `LocalAiAnalysisService` 与 `LocalLLMThread`
- 工具选择问题：优先看 `PromptTemplates`、`ToolExecutor`、`Agent模块说明.md`
