# 模块说明

> 版本: v2.4
> 更新日期: 2026-04-01

本文档说明当前项目各模块职责，以及最近新增 Agent 工具后的分层关系。

## 系统分层

```text
Main / GUI
  ↓
GUI Services
  ↓
Agent / Service
  ↓
Database / App / Core / Hardware
```

## 1. GUI 层

主要位于：

- `gui/src/`
- `gui/include/`

职责：

- 页面与组件渲染
- 用户交互
- 展示 AI 流式输出
- 展示工具调用、工具结果、思考状态

关键页面：

- `recognition_page`
- `dashboard_page`
- `attendance_page`
- `user_management_page`
- `settings_page`

## 2. GUI Services 层

主要位于：

- `include/gui_services/`
- `src/gui_services/`

职责：

- 把 GUI 与业务 / Agent 解耦
- 管理本地 / 远端 AI 生命周期
- 聚合天气、新闻、节假日等看板服务

关键服务：

- `AiAnalysisService`
  远端 AI 服务，支持 OpenAI 兼容接口
- `LocalAiAnalysisService`
  本地 RKLLM 服务
- `AiPromptBuilder`
  普通分析模式提示词组装
- `LlmProtocolAdapter`
  统一解析不同远端 SSE 协议

## 3. Agent 层

主要位于：

- `include/agent/`
- `src/agent/`

职责：

- 执行 ReAct 循环
- 管理工具注册与执行
- 管理对话记忆
- 管理增量 answer / reasoning 解析

关键组件：

- `ReactAgent`
- `AgentService`
- `ToolRegistry`
- `ToolExecutor`
- `ConversationMemory`
- `IncrementalResponseParser`

## 4. Tools 层

主要位于：

- `include/tools/`
- `src/tools/`

当前内置工具：

- `query_attendance`
- `lookup_user_attendance`
- `lookup_department_attendance`
- `lookup_attendance_ranking`
- `lookup_missing_attendance`
- `query_user`
- `system_info`
- `help`
- `calculator`

这些工具是当前 Agent 的业务能力核心，也是最近最需要保持文档与代码同步的部分。

## 5. Service 层

主要位于：

- `include/service/`
- `src/service/`

职责：

- 封装考勤业务与用户业务
- 对 DAO 层提供更稳定的业务接口

核心类：

- `AttendanceService`
- `UserService`

当前新增工具并没有直接写 SQL，而是优先复用这层能力，例如：

- 单员工考勤工具复用 `query_user_records`
- 部门、排行、缺卡工具复用 `get_all_users` 与 `query_records_range`

## 6. Database 层

主要位于：

- `include/database/`
- `src/database/`

职责：

- 负责 DAO 实现
- 提供数据库类型定义
- 管理 SQLite 连接与 SQL 执行

常用 DAO：

- `AttendanceRecordDAO`
- `UserDAO`
- `FaceFeatureDAO`

## 7. App 层

主要位于：

- `include/app/`
- `src/app/`

职责：

- 人脸识别多线程流水线编排
- 管理多线程流水线与同步互斥锁
- 管理 RKNN / RKLLM 模型生命周期

核心类：

- `FaceRecognitionApp`
  主应用管理类，负责检测/识别主循环，协调预处理线程、后处理线程以及模型推理。
- `ModelManager`
  模型管理器，管理 YOLOv8-Face（含 Zero-Copy 内存绑定）和 FaceNet 特征提取模型。
- `PreprocessingThread`
  **集成化硬件加速采集与预处理线程**。采用单线程热路径，合并了 V4L2 原始流拉取、MPP 任务级硬件解码、RGA 硬件图像处理以及 CPU 预处理降级机制。
- `FeatureLibrary`
  人脸数据库缓存特征库。
- `LocalLLMThread`
  本地大模型推理交互线程。

## 8. Core / Hardware 层

Core 层职责：

- **YOLOv8-Face 检测 (Zero-Copy)**
  基于物理内存绑定的人脸与五官关键点快速检测，推理时调用 `yolov8_face_run_zero_copy` 免拷贝极速处理，后处理直接从物理输出 `virt_addr` 拷贝，零输入数据拷贝。
- **FaceNet 特征提取**
  提取对齐人脸图像的 512 维高精度特征向量。
- **后处理与相似度计算**
  提取多路输出张量计算人脸框与关键点，计算特征向量的 Cosine 相似度。

Hardware 层职责：

- **V4L2 采集**
  只做 `VIDIOC_DQBUF` 抓取 MJPEG 原始码流包，提供高速压缩流访问。
- **MPP 任务级硬件解码 (Media Process Platform)**
  采用 MPP 的 **Advanced Task API**，压缩输入通过 `mpp_buffer_write()` 写入 MPP 输入缓冲；输出创建 DRM 格式的外部缓冲区并传递给解码任务，在硬件中高效率将 MJPEG 硬解为 NV12，导出 `dma-buf fd` 直通硬件下一环。
- **RGA 二维图像加速 (im2d)**
  零拷贝直连 MPP 输出与 NPU 输入：硬件一气呵成完成 **NV12颜色转换 + 水平镜像翻转 + 缩放 + Letterbox补黑边** 并直接写入 NPU 零拷贝输入物理内存中。
- **RKNN / RKLLM 运行时依赖**
  RK3588 开发板 NPU 硬件底层运行时库。

## 最近模块变化重点

最近一轮改动里，模块层面最值得注意的是：

1. 远端 Agent 使用 OpenAI 兼容接口
2. Agent 工具集从早期基础工具扩展到了个人、部门、排行、缺卡分析
3. 工具执行结果改成结构化观察块，不再只是旧式纯文本包装
4. 对话记忆与 reasoning 标签解析已按当前 Agent 行为修正
