# 模块说明

本文档详细介绍人脸识别考勤系统的模块职责与数据交互逻辑。

## 系统架构

系统采用 **C++17** 开发，基于分层模式设计，确保算法层、业务层与表现层的解耦。

```
┌─────────────────────────────────────────┐
│           Main (main_gui.cc)            │
│         基于 Qt5 的现代化界面            │
└─────────────────────────────────────────┘
                    ↓
┌─────────────────────────────────────────┐
│            Service 层 (业务)             │
│  - AttendanceService (考勤规则引擎)      │
│  - UserService (用户与特征管理)          │
└─────────────────────────────────────────┘
                    ↓
┌─────────────────────────────────────────┐
│            App 层 (流程编排)             │
│  - FaceRecognitionApp (流水线调度)       │
│  - 4级并行流水线线程 (采集/检测/识别/渲染) │
└─────────────────────────────────────────┘
                    ↓
┌─────────────────────────────────────────┐
│           Core 层 (算法内核)             │
│  - YOLOv8-face (NPU 硬件加速检测)        │
│  - MobileFaceNet (NPU 硬件加速识别)      │
└─────────────────────────────────────────┘
                    ↓
┌─────────────────────────────────────────┐
│         Hardware 层 (硬件抽象)           │
│  - V4L2 & mmap (零拷贝视频采集)          │
│  - RGA (硬件图像加速器)                  │
│  - RKNPU2 (神经网络处理器驱动)           │
└─────────────────────────────────────────┘
```

## 高性能流水线架构 (Pipeline)

系统通过 **4 个并行线程** 实现极致的吞吐量，充分压榨 RK3588 的 NPU 与 CPU 性能：

```
┌─────────────────┐      ┌───────────────┐      ┌────────────────┐      ┌─────────────────┐
│ Preprocessing   │      │ Main Thread   │      │ Postprocess    │      │ Recognition     │
│ Thread (T1)     │      │ (Detection T2)│      │ Thread (T2.5)  │      │ Thread (T3)     │
├─────────────────┤      ├───────────────┤      ├────────────────┤      ├─────────────────┤
│ • V4L2 mmap 采集 │ 队列 │ • YOLO 推理    │ 队列 │ • DFL/NMS 后处理│ 队列 │ • 人脸对齐       │
│ • RGA 镜像/缩放  │ ───> │   (仅 NPU)    │ ───> │   (CPU 密集型)  │ ───> │ • FaceNet 推理   │
│ • 正方形填充     │      │               │      │                │      │ • 特征匹配与渲染 │
└─────────────────┘      └───────────────┘      └────────────────┘      └─────────────────┘
```

### 关键优化点

1.  **零拷贝 (Zero-Copy)**:
    - 采集层通过 `mmap` 访问内核内存。
    - 应用层利用 `std::shared_ptr<cv::Mat>` 浅拷贝特性，帧数据在线程间流转时仅传递指针和引用计数，不发生像素级内存拷贝。
2.  **硬卸载 (Hardware Offload)**:
    - 图像缩放与格式转换全部由 **RGA** 硬件完成。
    - 模型推理全部由 **NPU** 完成。
3.  **负载均衡**:
    - 将耗时的 DFL/NMS 逻辑从 NPU 推理主线程剥离到 `PostprocessThread`，防止 NPU 等待 CPU 运算。

## 模块详解

### 1. 考勤业务模块 (AttendanceService)
不仅是数据库记录，还包含复杂的规则引擎：
- **工作时间表**: 支持分钟级上班/下班时间配置。
- **状态判定**: 自动计算迟到、早退时长。
- **去抖动设计**: 设定冷却时间（如 30 分钟），防止同一人连续识别导致的重复打卡。

### 2. 特征库模块 (FeatureLibrary)
- **并发安全**: 使用 `std::shared_mutex` 支持多线程同时读取特征进行比对，同时不阻塞管理界面的增删操作。
- **持久化**: 深度集成 SQLite，特征以 BLOB 格式存储，支持启动时毫秒级加载数千张人脸。

### 3. GUI 服务模块
在 `main_window.cc` 中集成的现代化功能：
- **AiAnalysisService (智能分析 - 核心亮点)**:
  - **混合双后端架构**: 
    - **云端模式**: 无缝对接腾讯云混元大模型 (SSE 流式)。
    - **本地模式**: 深度集成 **RKLLM**，在 RK3588 本地 NPU 上运行 2B/7B 级大模型。
  - **NPU 资源调度策略 (关键技术)**:
    - 由于 RKNN (人脸) 和 RKLLM (模型) 共享 NPU 计算单元，必须互斥使用。
    - **进入看板**: 自动释放 RKNN 模型及所有推理线程 → 加载 RKLLM。
    - **离开看板**: 自动释放 RKLLM 模型 → 重载 RKNN 并恢复实时人脸识别。
  - **LocalLLMThread**: 
    - 专用线程封装 RKLLM C API (`rkllm_run`, `rkllm_init`)。
    - 支持流式输出 (`RKLLM_RUN_NORMAL` 回调)。
    - 实现了完全独立于 UI 线程的异步初始化与推理。
  - **数据流**: 
    1. 用户在 `DashboardPage` 切换 "☁/🖥" 按钮选择后端。
    2. Service 层聚合 `AttendanceRecordDAO` 中的多日考勤数据（支持 1/7/30 天范围）。
    3. 智能截取数据以适应模型上下文限制 (Context Window)。
    4. 实时流式输出分析结果，延迟低至首字秒出（本地模式）。
- **WeatherService**: 实时天气抓取。
- **NewsService**: 热点滚动新闻。
- **HolidayService**: 节假日状态判定（决定是否需要考勤）。
- **AudioManager**: 基于 `QMediaPlayer` 的异步语音提示（如“签到成功”）。

## 性能参考指标 (RK3588)

- **端到端延迟**: < 35ms (单人)
- **吞吐量**: 35-45 FPS (1080P 输入)
- **CPU 占用**: < 15% (单核)
- **NPU 占用**: ~15% (基于 6 TOPS 总算力峰值)
