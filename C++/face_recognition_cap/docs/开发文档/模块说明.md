## 系统架构

人脸识别系统采用**分层架构**设计，将代码组织为三个层次：

```
┌─────────────────────────────────────────┐
│           Main (程序入口)                │
│         src/main.cc                     │
└─────────────────────────────────────────┘
                    ↓
┌─────────────────────────────────────────┐
│            App 层 (应用层)               │
│  - FaceRecognitionApp (主应用)          │
│  - ModelManager (模型管理)               │
│  - FeatureLibrary (特征库管理)           │
│  - PreprocessingThread (采集+预处理)     │
│  - PostprocessThread (YOLO后处理)        │
│  - RecognitionThread (识别+渲染)         │
│  - PerformanceMonitor (性能监控)         │
└─────────────────────────────────────────┘
                    ↓
┌─────────────────────────────────────────┐
│           Core 层 (核心算法)             │
│  - YOLOv8-face (人脸检测)               │
│  - FaceNet (特征提取)                    │
│  - PostProcess (后处理工具)              │
└─────────────────────────────────────────┘
                    ↓
┌─────────────────────────────────────────┐
│         Hardware 层 (硬件接口)           │
│  - CameraUtil (摄像头控制)               │
│  - RGA (硬件加速)                        │
│  - RKNN (NPU 推理)                       │
└─────────────────────────────────────────┘
```

## 流水线多线程架构

系统采用**四线程流水线**架构，最大化 NPU 利用率：

```
┌─────────────────────────────────────────────────────────────────────┐
│                        流水线多线程架构                               │
├─────────────────────────────────────────────────────────────────────┤
│                                                                     │
│  线程1 (PreprocessingThread)      线程2 (主循环)       线程2.5 (Postprocess)  │
│  ┌────────────────────────┐       ┌────────────────┐   ┌────────────────┐    │
│  │ 摄像头采集 (~0.6 ms)    │ 队列  │ YOLO推理 (~7 ms) │ 队列│ DFL/NMS (~3 ms) │    │
│  │ RGA预处理 (~0.8 ms)     │ ───> │ (仅NPU)       │──>│ (CPU)          │    │
│  └────────────────────────┘       └────────────────┘   └────────────────┘    │
│                                                             │                │
│                                                             │ 队列           │
│                                                             ▼                │
│                                                 ┌──────────────────────────┐ │
│                                                 │ 线程3 (RecognitionThread) │ │
│                                                 │ • 人脸对齐 (~2 ms)        │ │
│                                                 │ • FaceNet (~6 ms)         │ │
│                                                 │ • 特征匹配 (~0.4 ms)      │ │
│                                                 │ • 渲染显示                │ │
│                                                 └──────────────────────────┘ │
│                                                                     │
├─────────────────────────────────────────────────────────────────────┤
│ 瓶颈: YOLO推理 / 后处理 / 识别三者中的最大值                         │
└─────────────────────────────────────────────────────────────────────┘
```

### 架构优势

| 特性 | 描述 |
|------|------|
| **流水线并行** | 采集、检测、识别三阶段并行执行 |
| **瓶颈隔离** | YOLO检测独占主线程，不受其他阶段影响 |
| **丢帧策略** | 队列满时丢弃旧帧，保持实时性 |
| **零等待** | 各线程异步执行，无阻塞等待 |

## 分层设计

### 1. Main 层

**职责**: 程序入口，参数解析

**文件**: `src/main.cc`

**功能**:
- 解析命令行参数
- 创建 `FaceRecognitionApp` 实例
- 调用初始化和运行方法
- 处理退出逻辑

---

### 2. App 层

**职责**: 应用逻辑和流程控制

**目录**: `include/app/`, `src/app/`

#### 2.1 FaceRecognitionApp

**文件**: `face_recognition_app.h/cc`

**职责**:
- 协调所有模块的初始化
- 主循环：只执行 YOLO 检测
- 管理应用生命周期

**核心流程**:
```
initialize() {
    1. 初始化模型 (ModelManager)
    2. 加载特征库 (FeatureLibrary)
    3. 初始化摄像头 (CameraUtil)
    4. 启动采集预处理线程 (PreprocessingThread)
    5. 启动识别线程 (RecognitionThread)
}

run() {
    while (running) {
        1. 从预处理队列获取图像
        2. YOLO 人脸检测 (主线程瓶颈)
        3. 提交到识别队列
        4. 性能统计
    }
}

cleanup() {
    1. 停止所有线程
    2. 关闭摄像头
    3. 释放模型
}
```

#### 2.2 PreprocessingThread

**文件**: `preprocessing_thread.h/cc`

**职责**:
- **摄像头采集** (USB/MIPI)
- RGA 硬件加速的图像翻转和缩放
- 输出队列管理（丢弃旧帧）

**线程循环**:
```cpp
while (running) {
    1. 从摄像头读取一帧
    2. RGA 翻转 (镜像)
    3. RGA 缩放 (640x360)
    4. 放入输出队列 (最多2帧)
}
```

#### 2.3 RecognitionThread

**文件**: `recognition_thread.h/cc`

**职责**:
- 人脸对齐 (similarTransform + warpPerspective)
- FaceNet 特征提取
- 特征匹配
- 结果渲染和显示

**线程循环**:
```cpp
while (running) {
    1. 从识别队列获取任务
    2. 对每个人脸:
       - 人脸对齐
       - FaceNet 推理
       - 特征匹配
       - 绘制结果
    3. 显示 (imshow) 或回调 (GUI)
}
```

#### 2.4 ModelManager

**文件**: `model_manager.h/cc`

**职责**:
- 加载和管理 RKNN 模型
- 配置模型输入输出
- 提供模型推理接口
- 释放模型资源

**管理的模型**:
- YOLOv8-face: 人脸检测模型
- MobileFaceNet: 特征提取模型 (512维)

#### 2.5 FeatureLibrary

**文件**: `feature_library.h/cc`

**职责**:
- 从数据库/文件系统加载特征库
- 管理特征向量和用户ID映射
- 提供特征匹配功能
- 计算余弦相似度

#### 2.6 PerformanceMonitor

**文件**: `performance_monitor.h/cc`

**职责**:
- 统计各阶段耗时
- FPS 平滑计算
- 定期打印性能报告

**输出示例**:
```
============ 流水线性能分析 (平均 10 帧) ============
┌─────────────────────────────────────────────────────┐
│ 线程1 [采集+RGA]:          异步 (不阻塞)            │
├─────────────────────────────────────────────────────┤
│ 线程2 [YOLO检测]:    26.21 ms  (38.15 FPS)         │
├─────────────────────────────────────────────────────┤
│ 线程3 [识别+渲染]:    8.65 ms  (115.6 FPS)         │
│   ├─ 人脸对齐:        2.09 ms                       │
│   ├─ FaceNet:         6.17 ms                       │
│   └─ 特征匹配:        0.39 ms                       │
└─────────────────────────────────────────────────────┘
实际 FPS: 35.50   理论最大: 38.15 FPS
瓶颈: 线程2 (YOLO检测)
========================================================
```

### 3. Core 层

**职责**: 核心算法实现

**目录**: `include/core/`, `src/core/`

#### 3.1 YOLOv8-face

**文件**: `yolov8_face.h/cc`

**职责**:
- 人脸检测模型推理
- 输出人脸框和关键点

**输入**: 640x640 RGB 图像
**输出**: 人脸框 + 5个关键点（双眼、鼻子、嘴角）

#### 3.2 FaceNet (MobileFaceNet)

**文件**: `facenet.h/cc`

**职责**:
- 人脸特征提取
- 输出 512 维特征向量

**输入**: 112x112 对齐后的人脸图像
**输出**: 512 维归一化特征向量

#### 3.3 PostProcess

**文件**: `postprocess.h/cc`

**职责**:
- 人脸对齐变换 (similarTransform)
- 余弦相似度计算
- L2 归一化
- NMS 后处理

---

**职责**: 硬件接口封装

- V4L2 接口封装

**支持模式**:
- USB 同步模式

### 队列策略

| 队列 | 大小 | 策略 | 说明 |
|------|------|------|------|

| 识别任务队列 | 2 | 丢弃旧帧 | 防止积压 |

## 性能优化

### 多线程流水线优化

**优化前** (单线程):
```
摄像头读取 → 预处理 → 检测 → 识别 → 显示
总耗时: 35-40ms (25-28 FPS)
```

**优化后** (四线程流水线):
```
线程1: 采集+预处理 (异步，~1.4ms)
线程2: YOLO推理 (NPU，~7ms)
线程2.5: YOLO后处理 (DFL/NMS，CPU，~3ms)
线程3: 识别+渲染 (异步，~8.6ms)

流水线吞吐: 取决于 max(7ms, 3ms, 8.6ms) ≈ 8.6ms/帧（理论），实际受队列和显示影响
```

**性能提升**: 线程拆分后，检测 CPU 开销下降，NPU 与后处理解耦，峰值 FPS 提升，抖动降低

### 各阶段耗时 (1280x720, 1人)

| 阶段 | 耗时 (ms) | 线程 | 说明 |
|------|----------|------|------|
| 摄像头读取+RGA | ~1.4 | 线程1 | 已计时 |
| YOLO推理 | ~7 | 线程2 | NPU |
| YOLO后处理 | ~3 | 线程2.5 | DFL + NMS |
| 人脸对齐 | ~2.1 | 线程3 | 异步 |
| FaceNet | ~6.2 | 线程3 | 异步 |
| 特征匹配 | ~0.4 | 线程3 | 异步 |
| 渲染显示 | <0.1 | 线程3 | 异步 |

**瓶颈**: max(线程1, 线程2, 线程2.5, 线程3)

### FPS 性能

| 场景 | FPS | 帧时间 | 瓶颈 |
|------|-----|--------|------|
| 1280x720, 0人 | 受显示/队列影响 | ~8-10ms | 后处理/识别 |
| 1280x720, 1人 | 同上 | ~9-12ms | 后处理/识别 |
| 1280x720, 3人 | 同上 | ~11-15ms | 后处理 + 识别 |

```cpp
int init_new_detector(const char* model_path);

```

### 2. 修改识别模型

替换 FaceNet 模型:
```cpp
// 在 RecognitionThread 中修改
model_manager_->get_new_facenet_ctx();
```

### 3. 添加活体检测

在识别线程中添加:
```cpp
void RecognitionThread::process_task(RecognitionTask& task) {
    // 现有流程
    cv::Mat aligned = align_face(...);

    // 添加活体检测
    bool is_alive = liveness_detector_->detect(aligned);
    if (!is_alive) continue;
    
    // 继续特征提取
    facenet_inference(...);
}
```

## 最佳实践

### 1. 线程安全

- 使用 `std::mutex` 保护共享队列
- 使用 `std::atomic` 保护简单标志
- 避免跨线程共享 cv::Mat (使用 clone)

### 2. 资源管理

- 使用 RAII 管理模型资源
- 线程在析构时自动停止
- 队列限制大小防止内存溢出

### 3. 性能调优

- 队列大小设为 2，平衡延迟和吞吐
- 使用丢帧策略保持实时性
- 定期打印性能报告便于调优

## 总结

### 架构特点

1. **流水线并行**: 三线程流水线，最大化 NPU 利用率
2. **瓶颈隔离**: YOLO 检测独占主线程
3. **异步处理**: 采集、识别、渲染异步执行
4. **实时保证**: 丢帧策略确保实时性

### 性能指标

| 指标 | RGA启用 | RGA禁用 | 说明 |
|------|---------|---------|------|
| 实际 FPS | 35-38 | 25-28 | RGA提供硬件加速 |
| 理论最大 FPS | ~38 | ~28 | 瓶颈在YOLO检测 |
| 识别延迟 | ~35ms | ~40ms | 包含预处理时间 |
| 内存占用 | ~30MB | ~32MB | OpenCV使用稍多内存 |
| Valgrind警告 | 有 | 无 | RGA库存在未初始化变量 |

### 配置选项

- `Config::Performance::USE_RGA`: 控制是否启用RGA硬件加速
  - `true`: 启用RGA加速，性能更好但Valgrind有警告
  - `false`: 禁用RGA，使用OpenCV降级，完全避免警告
