## 核心架构

系统采用 **DAO (Data Access Object)** 模式实现数据库解耦。所有数据库操作通过 `DatabaseManager` 单例进行连接管理，并由具体的 DAO 类执行 SQL。

### 目录结构
- `include/database/`: DAO 接口与 `database_types.h`。
- `src/database/`: SQLite SQL 语句实现。
- `include/service/`: `AttendanceService` 等更高层的业务封装。

## 表结构设计

### 1. users (人员信息)
存储用户的基本身份信息。
| 字段 | 类型 | 说明 |
| :--- | :--- | :--- |
| user_id | INTEGER | 主键 (Primary Key) |
| user_name | TEXT | 姓名 (Unique) |
| employee_id | TEXT | 工号 |
| department | TEXT | 部门名称 |
| status | INTEGER | 1=启用, 0=禁用 |

### 2. face_features (人脸特征)
存储 512 维特征向量，支持一人多脸。
| 字段 | 类型 | 说明 |
| :--- | :--- | :--- |
| feature_id | INTEGER | 主键 |
| user_id | INTEGER | 外键 (FK: users.user_id) |
| feature_vector | BLOB | **512维 float 数组 (2048字节)** |
| feature_quality | REAL | 注册时的画质评分 |

### 3. attendance_records (考勤记录)
记录每一次识别成功的打卡。
| 字段 | 类型 | 说明 |
| :--- | :--- | :--- |
| record_id | INTEGER | 主键 |
| user_id | INTEGER | 用户 ID |
| check_time | INTEGER | Unix 时间戳 (C++ std::time_t) |
| check_type | INTEGER | 1=签到, 2=签退 |
| status | INTEGER | 1=正常, 2=迟到, 3=早退 |
| similarity | REAL | 识别时的相似度分数 |

## 关键 API 使用

### 考勤服务集成
业务层无需直接编写 SQL，通过 `AttendanceService` 操作：

```cpp
auto service = service::AttendanceService(&db::DatabaseManager::instance());

// 自动判断逻辑：
// 1. 检查今日是否已签到。
// 2. 根据上班时间配置计算是否迟到。
// 3. 记录到数据库。
int record_id = service.record_attendance(user_id, "姓名", 0.92);
```

### 特征库热加载
`FeatureLibrary` 支持直接从数据库同步：
```cpp
// 启动时加载所有启用用户的最新特征
feature_library.load_from_database(&db::DatabaseManager::instance());
```

## db_tool 工具

项目内置了名为 `db_tool` 的命令行工具，用于脱离 GUI 进行数据运维。

```bash
# 初始化一个全新的数据库文件
./db_tool init ./data.db

# 手动添加人员
./db_tool add_user ./data.db "陈某" "技术部"

# 统计考勤数据
./db_tool stats ./data.db
```

## 性能优化建议

1.  **索引**: 系统已为 `user_id` 和 `check_time` 建立索引，保证在记录数过万时查询依然秒开。
2.  **事务**: 批量导入特征时，`db_tool` 默认开启事务，提升写入速度 10 倍以上。
3.  **BLOB 存储**: 特征向量使用 BLOB 存储而非字符串拼接，极大降低了内存序列化的 CPU 消耗。
