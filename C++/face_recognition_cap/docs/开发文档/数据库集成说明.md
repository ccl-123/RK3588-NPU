# 数据库集成说明

> 版本: v2.4
> 更新日期: 2026-04-01

本文档说明当前项目的 SQLite 集成方式，以及数据库如何支撑 Agent 工具系统。

## 核心结构

系统采用 DAO + Service 两层结构：

```text
SQLite
  ↓
DatabaseManager
  ↓
DAO (AttendanceRecordDAO / UserDAO / FaceFeatureDAO)
  ↓
Service (AttendanceService / UserService)
  ↓
Agent Tools / GUI Services / Main App
```

这样做的目的：

- SQL 与业务逻辑分离
- 工具层不直接写数据库语句
- 便于后续扩展部门、排行、缺卡等分析能力

## 关键表

### 1. `users`

存储人员信息：

- `user_id`
- `user_name`
- `employee_id`
- `department`
- `position`
- `status`

### 2. `face_features`

存储用户人脸特征：

- `feature_id`
- `user_id`
- `feature_vector`
- `feature_quality`

### 3. `attendance_records`

存储考勤记录：

- `record_id`
- `user_id`
- `user_name`
- `check_time`
- `check_type`
- `status`
- `similarity`
- `device_id`
- `location`

## 当前业务接口

### AttendanceService

当前 Agent 工具最常复用这些接口：

```cpp
query_user_records(...)
query_records_by_date(...)
query_records_range(...)
get_statistics(...)
get_statistics_range(...)
```

### UserService

当前 Agent 工具最常复用这些接口：

```cpp
get_user(...)
get_all_users(...)
get_feature_count(...)
```

## Agent 工具与数据库关系

### 全局考勤工具

- `query_attendance`
  依赖：
  - `query_records_by_date`
  - `query_records_range`
  - `get_statistics`
  - `get_statistics_range`

### 单员工考勤工具

- `lookup_user_attendance`
  依赖：
  - `get_user`
  - `get_all_users`
  - `query_user_records`

### 部门考勤工具

- `lookup_department_attendance`
  依赖：
  - `get_all_users`
  - `query_records_range`

### 排名工具

- `lookup_attendance_ranking`
  依赖：
  - `get_all_users`
  - `query_records_range`

### 缺卡缺勤工具

- `lookup_missing_attendance`
  依赖：
  - `get_all_users`
  - `query_records_by_date`
  - `query_records_range`

## `db_tool`

项目内置数据库运维工具：

```bash
./db_tool init ./data.db
./db_tool add_user ./data.db "陈某" "技术部"
./db_tool stats ./data.db
```

用途：

- 初始化数据库
- 添加测试用户
- 做基础统计验证

## 性能说明

当前数据库设计已经足以支撑：

- 单日考勤统计
- 区间记录查询
- 单员工历史查询
- Agent 工具在看板中的实时分析

但要注意：

- 部门排行和缺卡分析目前仍以 Service 层结果做二次聚合
- 如果后续继续上更复杂的跨部门 TopN、长时间趋势排行，可以考虑继续往 DAO 层补专用聚合 SQL

## 开发建议

如果后续新增 Agent 工具需要数据库能力，优先顺序建议是：

1. 先看 `AttendanceService` / `UserService` 是否已有可复用接口
2. 若无，再补 DAO 层聚合方法
3. 不建议直接在工具实现里写原始 SQL
