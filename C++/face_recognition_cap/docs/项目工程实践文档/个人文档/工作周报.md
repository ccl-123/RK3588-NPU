## 第一周工作周报

| 时间 | 2025年11月18日 至 2025年11月24日 | 周次 | 1 |
|------|--------------------------------|------|---|

| 工作内容 |
|----------|
| 1. **需求分析与方案设计**：分析人脸识别考勤系统的功能需求，确定技术方案：使用 RK3588 平台 + NPU 加速，采用 YOLOv8-face 人脸检测 + MobileFaceNet 特征提取的双模型架构 |
| 2. **开发环境搭建**：在 RK3588 开发板上安装 Ubuntu 22.04 系统，配置 RKNN-Toolkit2 开发工具链、OpenCV、Qt5 等依赖库，验证 NPU 硬件加速功能正常 |
| 3. **AI 模型研究与转换**：研究 YOLOv8-face 和 MobileFaceNet 模型结构，编写 ONNX 到 RKNN 的转换脚本，完成 INT8 量化，使用 WIDER FACE 数据集作为量化校准集 |
| 4. **项目架构设计**：设计四层软件架构 (Main → App → Core → Hardware)，划分核心模块：ModelManager、FeatureLibrary、FaceRecognitionApp 等 6 个 App 层组件 |
| 5. **数据库表结构设计**：设计 SQLite 数据库 ER 图，包含 users (用户表)、face_features (人脸特征表)、attendance_records (考勤记录表)、attendance_rules (考勤规则表)、system_logs (系统日志表) 共 5 张核心表 |
| 6. **核心推理模块开发**：实现 RKNN 模型加载、NPU 推理、后处理逻辑；完成 YOLOv8-face 的 DFL 解码、NMS 过滤、5 点关键点提取；实现 MobileFaceNet 的 512 维特征提取和 L2 归一化 |
| 7. **人脸对齐算法实现**：基于 5 点关键点实现仿射变换，将检测到的人脸对齐到 112×112 标准尺寸，确保特征提取的一致性 |
| 8. **命令行版本验证**：完成命令行版本的人脸识别功能，验证检测→对齐→特征提取→比对的完整流程，静态图片识别测试通过 |

## 第二周工作周报

| 时间 | 2025年11月25日 至 2025年12月1日 | 周次 | 2 |
|------|-------------------------------|------|---|

| 工作内容 |
|----------|
| 1. **实时摄像头集成**：实现 USB 摄像头 (1280×720) 实时采集，开发异步读取 + 双缓冲机制，摄像头读取延迟从 31ms 降至 0.76ms |
| 2. **RGA 硬件加速优化**：使用 RK3588 的 RGA 2D 加速器进行图像翻转和缩放，替代 OpenCV CPU 处理；实现三线程并行架构 (采集→预处理→推理)，FPS 从 14.2 提升至 56.6 |
| 3. **数据库模块实现**：实现 DatabaseManager 单例模式管理连接，开发 UserDAO、FaceFeatureDAO、AttendanceRecordDAO 三个数据访问对象，支持用户增删改查和特征存储 |
| 4. **考勤服务层开发**：实现 AttendanceService 考勤业务逻辑，包括签到/签退判断 (12:00 分界)、防重复签到检测 (可配置间隔)、考勤记录自动保存 |
| 5. **特征库管理**：实现 FeatureLibrary 模块，支持从数据库加载人脸特征，实现余弦相似度比对算法，设置识别阈值 (默认 0.5) 判断身份 |
| 6. **Qt5 GUI 框架搭建**：创建 MainWindow 主窗口，设计实时识别页、用户管理页、考勤查询页、系统设置页四个主页面的 UI 布局 |
| 7. **实时识别界面开发**：实现视频显示组件 (VideoDisplayWidget)，添加人脸检测框和关键点绘制，显示识别结果 (姓名、置信度)、FPS 和系统状态 |
| 8. **用户管理功能**：实现用户列表展示、人脸注册对话框 (多角度采集)、用户删除功能；建立信号槽机制实现跨窗口数据同步 |

## 第三周工作周报

| 时间 | 2025年12月2日 至 2025年12月8日 | 周次 | 3 |
|------|------------------------------|------|---|

| 工作内容 |
|----------|
| 1. **语音播报系统**：开发 AudioManager 异步音频模块，实现签到成功、签退成功、重复签到、陌生人检测等场景的语音提示；添加播放冷却机制避免重复播报 |
| 2. **配置持久化**：实现 ConfigManager 模块，将识别阈值、音频设置、考勤规则等配置保存到 INI 文件，支持应用重启后自动加载 |
| 3. **天气信息集成**：接入 Open-Meteo API 获取实时天气、AQI 空气质量、UV 紫外线指数；实现 IP 自动定位和手动城市选择；添加一言 API 每日一句功能 |
| 4. **主题切换功能**：设计深色/浅色两套 QSS 样式表，实现一键主题切换；美化签到状态标签 (签到绿色渐变、签退蓝色渐变) |
| 5. **UI 布局优化**：修复用户名长度变化导致的界面抖动问题，使用固定宽度容器约束布局；调整字体大小和间距，解决长名字截断问题 |
| 6. **Bug 修复与调优**：修复时区不一致导致重复签到判断失效的问题；调整检测置信度阈值 (0.7→0.5) 解决近距离检测失败；优化陌生人检测逻辑 (持续 2 秒后播报) |
| 7. **系统测试**：进行功能测试 (注册、识别、签到签退)、性能测试 (FPS、响应时间)、稳定性测试 (长时间运行)，记录测试结果 |
| 8. **文档整理**：编写系统架构文档、数据库设计文档、API 接口文档、用户使用手册；整理项目成果登记表和工作周报 |
