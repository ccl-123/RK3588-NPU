## 1 项目背景及意义

### 1.1 项目背景

随着人工智能技术的快速发展，人脸识别技术已广泛应用于安防、金融、教育等领域。传统的考勤方式（如打卡机、指纹识别）存在代打卡、接触式卫生问题、排队耗时等弊端。基于人脸识别的智能考勤系统能够实现非接触式、高效率的身份验证，具有广阔的应用前景。

近年来，边缘计算和嵌入式 AI 技术的成熟，使得在低功耗设备上部署深度学习模型成为可能。瑞芯微 RK3588 芯片集成了 6 TOPS 算力的 NPU（神经网络处理单元），能够在边缘端高效运行人脸检测和识别模型，无需依赖云端服务器，保护用户隐私的同时降低网络延迟。

### 1.2 项目意义

1. **技术价值**：探索边缘 AI 在实际场景中的落地应用，验证 RK3588 NPU 的深度学习推理能力
2. **应用价值**：解决传统考勤方式的痛点，提供非接触、高效、准确的考勤解决方案
3. **学习价值**：综合运用嵌入式系统、深度学习、数据库、GUI 开发等多领域知识，提升工程实践能力

## 2 项目介绍

### 2.1 系统概述

本项目开发了一套基于 EC-A3588Q（RK3588）平台的人脸识别智能考勤系统，采用 YOLOv8n-face 进行人脸检测，MobileFaceNet 进行人脸特征提取，实现实时人脸识别和自动考勤功能。

### 2.2 技术架构

系统采用五层架构设计，自上而下分别为：

1. **GUI 层**：基于 Qt5 的图形用户界面，包含实时识别页、用户管理页、考勤查询页、系统设置页
2. **Service 层**：考勤业务逻辑和用户管理服务，包含 AttendanceService、UserService
3. **App 层**：应用核心逻辑，包含 ModelManager（模型管理）、FeatureLibrary（特征库）、FaceRecognitionApp（识别应用）
4. **Core 层**：AI 模型推理和后处理算法，包含 YOLOv8-face、MobileFaceNet、PostProcess
5. **Hardware 层**：硬件加速和设备驱动，包含 NPU/RKNN、RGA 2D、Camera

### 2.3 核心功能

1. **人脸检测**：YOLOv8n-face 模型，支持多人脸检测，输出 5 点关键点
2. **人脸识别**：MobileFaceNet 提取 512 维特征向量，余弦相似度比对
3. **自动考勤**：智能判断签到/签退，防重复签到，考勤记录持久化
4. **用户管理**：用户注册、删除、人脸特征采集和存储
5. **数据查询**：按日期/用户查询考勤记录，支持导出
6. **语音播报**：签到成功、签退成功、陌生人检测等场景语音提示

### 2.4 性能指标

1. **实时帧率**：30+ FPS
2. **检测延迟**：<30ms
3. **识别准确率**：>99%（注册用户）
4. **支持人数**：1000+

## 3 本人主要工作

### 3.1 AI 模型部署

1. **模型转换与量化**：将 YOLOv8n-face (ONNX) 和 MobileFaceNet (ONNX) 转换为 RKNN 格式，使用 WIDER FACE 数据集进行 INT8 量化校准，模型体积减小 75%，推理速度提升 3 倍
2. **后处理算法实现**：实现 YOLOv8 的 DFL (Distribution Focal Loss) 解码、NMS (非极大值抑制)、5 点关键点提取等后处理逻辑
3. **人脸对齐算法**：基于 5 点关键点实现仿射变换，将人脸对齐到 112×112 标准尺寸

### 3.2 性能优化

1. **异步摄像头读取**：实现双缓冲机制，摄像头读取延迟从 31ms 降至 0.76ms
2. **RGA 硬件加速**：使用 RK3588 的 RGA 2D 加速器进行图像翻转和缩放
3. **多线程流水线**：设计三线程并行架构（采集→预处理→推理），FPS 从 14.2 提升至 56.6

### 3.3 数据库系统

1. **表结构设计**：设计 5 张核心表（用户、特征、考勤、规则、日志）
2. **DAO 模式实现**：封装 UserDAO、FaceFeatureDAO、AttendanceRecordDAO 数据访问对象
3. **业务逻辑层**：实现 AttendanceService 考勤服务，包含签到判断、防重复检测等

### 3.4 GUI 界面开发

1. **Qt5 界面框架**：开发实时识别页、用户管理页、考勤查询页、系统设置页四个主页面
2. **主题系统**：设计深色/浅色两套 QSS 样式表，支持一键切换
3. **辅助功能**：集成天气显示、语音播报、配置持久化等功能

## 4 得意及创新之处

### 4.1 三线程流水线架构

传统的单线程处理方式中，摄像头读取、图像预处理、模型推理是串行执行的，造成 CPU/NPU 资源利用率低。本项目设计了三线程流水线架构：

```
时间轴 →
线程1(采集):   [帧1采集][帧2采集][帧3采集][帧4采集]...
线程2(预处理):      [帧1预处理][帧2预处理][帧3预处理]...
线程3(推理):            [帧1推理][帧2推理][帧3推理]...
```

通过流水线并行，系统吞吐量提升 **272%**（14.2 FPS → 56.6 FPS）。

### 4.2 RGA 硬件加速

充分利用 RK3588 的 RGA 2D 加速器进行图像处理，避免 CPU 参与像素操作：
- 图像翻转：`imflip(IM_HAL_TRANSFORM_FLIP_H)` 替代 `cv::flip()`
- 图像缩放：`improcess()` 替代 `cv::resize()`
- 预处理耗时从 6.92ms 降至 4.75ms，降低 **31.4%**

### 4.3 模型量化优化

使用人脸专用数据集（WIDER FACE）进行 INT8 量化校准，相比使用通用数据集（COCO），人脸检测精度提升约 5%，避免了量化精度损失。

### 4.4 智能考勤策略

设计了多层次的考勤判断策略：
1. **时间分界**：12:00 前为签到模式，12:00 后为签退模式
2. **连续确认**：需连续 5 帧识别成功才触发签到，避免误识别
3. **防重复机制**：可配置的冷却时间（默认 5 分钟），防止重复打卡
4. **陌生人检测**：持续 2 秒检测到陌生人后播放提示音

## 5 个人工作不足及待改善之处

### 5.1 现有不足

1. **活体检测缺失**：目前系统无法防范照片攻击，存在安全隐患
2. **光照适应性**：在极端光照条件下（强逆光、暗光），检测准确率下降
3. **多人同时识别**：当多人同时出现在画面中时，识别效率和准确性有待提升
4. **模型更新机制**：新注册用户需要重启应用才能生效，缺乏热更新能力

### 5.2 改进方向

1. **引入活体检测**：集成 Silent Face Anti-Spoofing 等活体检测模型，防止照片/视频攻击
2. **图像增强**：添加自适应直方图均衡化（CLAHE）预处理，提升弱光环境下的检测效果
3. **特征库热更新**：实现特征库的动态加载机制，新用户注册后立即生效
4. **分布式部署**：支持多设备协同工作，统一管理考勤数据
